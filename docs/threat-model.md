# Threat model

Assets: the admission capacity of the origin (who gets in, and how fast), the integrity of the
admission rate, the admin API, and the availability of the site.

Trust boundaries: the visitor's browser (untrusted), Cloudflare's edge and Transform Rules (trusted),
the edge handler and the coordinator Durable Object (same Worker, trusted), the origin.

| Threat | Mitigation | Residual risk |
|---|---|---|
| Forged or modified cookies (session, ticket, provisional, bypass) | HMAC-SHA256, 128-bit tag, key id, room id bound in the MAC input, constant-time comparison, strict decoding | Key compromise: rotate keys (runbook). |
| Cookie theft (XSS on the site, malware) | `__Host-` prefix, `HttpOnly`, `Secure`, `SameSite=Lax`; sessions expire after `D` minutes of inactivity, and after `sessionMaxMinutes` (4 h by default) however active | A stolen session cookie works until it expires, like any bearer cookie. |
| Session sharing (one admitted user distributes the cookie) | Session cookies are counted once per minute per cookie: sharing does not inflate the active estimate, but the shared cookie admits several people; its total lifetime is bounded by `sessionMaxMinutes` | Same as any cookie-based admission. Not detectable without client binding. |
| Waiting-room cookie stored by a shared cache (corporate proxy, another CDN) and served to other visitors | Every response that carries a waiting-room cookie is made private: `Cache-Control: private` without `public` or `s-maxage`, `CDN-Cache-Control` and `Surrogate-Control` removed. The zone cache is looked up before the cookie is added | A cache that ignores `Cache-Control: private` is broken anyway. |
| Skipping the queue through the early exit (`/index.php/x.css`, `/cart;.js`, `/orders/checkout.json`) | Early exit for `GET`/`HEAD` only; refused for `;`, encoded slashes and a script followed by a path; dynamic-prone extensions (`json`, `xml`, `txt`, `pdf`) left out of the example | The origin must serve the listed extensions from static files only ([routing](routing.md#inside-the-worker)): an extension it routes to a dynamic page is a way around the room. |
| Ticket copy and replay | Local refusal per isolate; coordinator detects duplicates and revokes the copies (≤ one TTL); first redemption keeps its session | Up to one admission per isolate until the next flush. |
| Holding an old ticket | Tickets expire `redeemGraceSec` after `admitAt` | — |
| Bots that keep no cookie | Never get a slot (lazy claim in open mode; a reservation needs a provisional cookie) | Bandwidth of waiting pages; use WAF/Bot rules. |
| Queue inflation: scripts reserving slots they never use. A reservation does not need a browser: fetch a page for a provisional cookie, then call `/__wr/reserve`. Each fake ticket delays every visitor behind it by `60 / R_eff` seconds | One ticket per provisional cookie, also across coordinator restarts (nonces stored in SQLite); cookie at least `reserveMinAgeSec` and at most `provisionalWindowSec` old; proof of work per ticket (`reservePowBits`); `Sec-Fetch-Site` checked when present; optional Turnstile; no-shows compensated by overbooking up to `overbookCap` | The minimum age and the proof of work only stop naive scripts: a native SHA-256 implementation solves 14 bits in milliseconds. Turnstile is the defence against a determined attacker. A successful flood fills the queue up to `maxWaitingTickets`, then new reservations are refused (`full`) until it drains: the coordinator stays healthy, legitimate newcomers wait for room. Per-IP quotas and per-IP rate limiting are deliberately not used: many legitimate visitors may share one address (companies, schools, mobile carrier NAT). |
| Forged `x-wr-bot` header | The Transform Rule sets the header to a shared secret (`WR_BOT_SECRET`, ≥ 32 characters) for allowed verified bots only; the Worker compares it in constant time and removes it before the origin; another rule removes client values. Without the rules, or with them in another order, a forged header is refused | The secret is stored in the zone's Transform Rules: whoever can read them can skip the queue. Rotate it like the other secrets. |
| Verified bots skipping the queue | Only the categories listed in the Transform Rule (search engines, link previews, ad landing-page checks by default) get the bot header; AI crawlers, SEO tools and other verified bots go through the room like visitors, and without JavaScript they never reserve a slot | A bot of an allowed category is relayed at any load: keep the list short. |
| Replaying a provisional cookie to claim several leased slots (open mode) | One leased slot per cookie in each isolate (claimed nonces remembered until the end of `provisionalWindowSec`) | Another isolate does not know the claim: a replay across isolates costs the client as much as a fresh cookie (one relayed page view per slot), and every slot is counted against `R`. |
| Bypass header brute force | Secret compared in constant time over SHA-256 digests; header removed before the origin | Use a long random secret and rotate it. |
| Signed link leakage | Bound to the hostname it was created for (MAC); expiry (max 30 days), label logged on every use, token removed from the URL by a redirect (`Referrer-Policy: no-referrer`) that always stays on the same host (leading slashes collapsed; link paths validated at creation) | A leaked link works on its hostname until it expires, for the whole hostname (the path is only the landing page); rotate the key to revoke all links. |
| Admin API abuse | Bearer token compared in constant time; every call logged; 404 when no token is configured; with `ADMIN_HOSTS`, served only on the operator hostname (404 on the site) ([operator access](operator-access.md)) | The token gives full control: protect it and generate it with `openssl rand`. A `workers.dev` hostname is guessable, so the hostname restriction alone is not authentication: the token is. |
| Metrics scraping | Basic auth, constant-time comparison; operator hostname like the admin API | Metrics reveal traffic levels; keep credentials private. |
| Dashboard access | Basic auth, constant-time comparison, 404 when not configured, strict CSP with nonce and `frame-ancestors 'none'`, `no-store`; failed attempts always logged (`dashboard_denied`). The dashboard credentials grant administration (mode, pause, rate, whitelist, signed links, any setting) through `/__wr/dashboard/admin/*`, with the same validation as the admin API; every change is logged (`admin_request` with `via: dashboard`) | Basic auth has no lockout: use a long random password, treat it like the admin token, and serve the dashboard on the operator hostname ([operator access](operator-access.md)). Give read-only views through the Prometheus metrics (Grafana), never the dashboard credentials. Each refresh costs one Durable Object request. |
| Cross-site request forgery on the dashboard | The browser resends basic auth credentials on any request to the origin, even one started by another site. A change is accepted only with an `Origin` equal to the dashboard origin, a JSON `Content-Type` (which another site cannot send without a CORS preflight, never granted) and, when present, `Sec-Fetch-Site: same-origin`; otherwise 403 and `dashboard_admin_refused` is logged. `frame-ancestors 'none'` prevents clickjacking | Browsers that send neither `Origin` nor `Sec-Fetch-Site` on such requests are refused, not trusted. |
| Coordinator overload (flood of reservations) | At most `reserveMaxInflight` reservation calls in flight per isolate, beyond which the edge answers `retry` without calling the coordinator; the checks above run before any coordinator call; RPC timeouts; while the room queues, a failed reservation answers `retry` and never gives a session, whatever the fail mode | Many isolates together can still exceed ≈ 1,000 req/s; the object then returns overload errors: queued visitors wait longer, the room does not open. Pages fail open or closed (`FAIL_MODE`, closed when unset) only when no snapshot is available, or in open mode when a lease cannot be refilled. |
| Log flooding (cost and noise): requests that produce a refusal or a waiting page | Waiting pages and refusals are logged with sampling and counted exactly in the metrics; invocation logs disabled | Errors are always logged: during a coordinator outage, one `fail_mode` line per request let through. |
| Whitelist that opens the room to everyone (typo such as `0.0.0.0/0`) | Blocks wider than `/8` (IPv4) or `/32` (IPv6) refused by the admin API; every change logged | A narrower but still wide block remains possible: review the whitelist (`GET whitelist`). |
| Coordinator restart during an event | State reloaded, high-water marks prevent double attribution, mode and pause kept | Up to 10 s of slots skipped; deployment freeze in the runbook. |
| Clickjacking / XSS on the waiting page | Strict CSP with per-response nonce, no external resource (except the optional Turnstile script), `form-action 'none'`, data embedded as escaped JSON | — |
| Waiting page cached by an intermediary | `Cache-Control: no-store` | — |
| Cache poisoning through the Worker | The Worker never changes cached content: cookies are added after the cache lookup | — |
| Secrets in the public repository | No secret, no deployment job; real configuration ignored by git; secret scanning enabled on the repository | — |
| Denial of service on the origin through excluded paths | Out of scope: excluded paths (API, webhooks) are not protected by the room by design | Use WAF and rate limiting rules. |

Out of scope: attacks on Cloudflare itself, compromise of the Cloudflare account (it can change the
Worker), and the origin's own security.
